# FH1 Desktop Editor Implementation Plan

> Execute inline with superpowers:executing-plans. User authorized autonomous implementation.

**Goal:** A standalone FH1 editing application with path onboarding, car library, donor-part copy/paste and DLC export.
**Architecture:** Python loopback backend embedded in a pywebview native Windows window. Existing Three.js editing and FH1 format routines remain authoritative.
**Tech Stack:** Python, numpy, pywebview/WebView2, Three.js, PyInstaller.
**Spec:** docs/superpowers/specs/2026-11-04-fh1-desktop-design.md

## Global Constraints
- Preserve original source edits and original 1.0.0 release.
- Dedicated desktop window; no browser launching in normal mode.
- Real FH1 data is read-only during verification; exports go to separate test outputs.
- Report offline versus in-game verification accurately.

## Review Focus
- Invalid remembered game path must still allow application startup and correction.
- Donor inspection/copy must not replace or stage the active car.
- Paste must repair LOD draw-list references and use unique buffer keys.
- Unsupported material/texture transfer must be surfaced before paste.
- Packaged assets, file downloads and closing the window must work in the native shell.
